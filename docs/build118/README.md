# Build118 Prefill 优化候选

实现两种互斥的CPU PTQ1优化：flag8字节查表、flag16 ARM NEON解码/整数点积。原始float缩放顺序不变，模型/量化/放置/线程数不变；生产不开启候选。已有flag4输入数组复用一起进入集中对照。

新增显式quick_prefill租约：16K/B8/Q4，保持完整身份、实际配置、取消/恢复与ABBA验证。旧B16故障标记不会被覆盖/清除；Quick未知请求、执行校验异常、失联watchdog和失败启动均保留其独立标记。正常完成后恢复生产上下文，统计漂移只标无效轮，不当作未知请求重放。

同一个Build118 IPA包含所有候选。Windows统一入口是 `RUN_PREFILL_COMPARE.cmd --url http://<iPad-IP>:8080`，一次比较flags4/8/16。默认单轮是探索，不自动晋级；`--rounds 5`用于确认，长输入另用`--prompt-tokens 2048`。报告包含正负变化、哈希/logits、实际CPU命中、内存与漂移。没有命中不能证明优化生效。

原子策略读取给未启用候选的CPU路径增加一次检查，其实际端到端开销也需要设备比较。CPU调用计数仅在benchmark期间开启，普通API不记录这些计数。不把CPU路径出现认定为故障根因，也不把CI算术测试当作性能收益。
