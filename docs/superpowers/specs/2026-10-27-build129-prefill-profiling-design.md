# Build129 等配置 Prefill profiling 设计草案

目标：在 Build129 派生构建中测量真实生产文本请求的 Prefill CPU/GPU 路径，保持模型、上下文及其创建参数、原生优化标志和生成语义不变。诊断结果不作为性能提升。

选择：使用专用、显式启用的单请求诊断作用域，复用已经加载的生产 context；不调用会重建 context 或配置候选 flags 的 benchmark start/configure。必须具备排他租约、请求前后 GPU 排空、原生 ABI 可用性核验、计数器重置/关闭及失败清理。任何条件不能证明时，返回 unavailable，不输出貌似有效的数据。收集期内禁止其他推理或视觉工作混入；不能证明进程范围排他时不宣称隔离。保留请求级 ID、准确配置及模型身份。CPU 节点和 GPU 命令缓冲区时间不相加为墙钟分解；分别报告覆盖和重叠限制。

替代方案：现有 benchmark 会重建 context 并改变 kv_unified、候选标志，不符合冻结基线；普通 API 直接打开全局计数器缺少排他与排空保证，不可信。设备外 Instruments 可辅助，但不替代可复现的请求级证据。

验证：先测试排他、并发拒绝、前后排空、失败清理、ABI 缺失和参数不变；由 iOS CI 构建诊断版，再对真实设备执行受限的短及约180-token请求。记录诊断开关的开销、结果一致性、温度/内存和原始响应；每次运行前后核对实际配置、身份及恢复状态，超时不自动重试。若无法证明这些前提则停止，并不选择优化候选。
